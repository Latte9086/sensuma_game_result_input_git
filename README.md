# 千スマ 対戦結果の報告

各台の固定 QR から選手が対戦を検索し、結果を送ります。本部は start.gg で台割り当て、呼び出し、棄権・DQ、代理入力を扱います。

## テスト環境の設定

1. テスト用 Google スプレッドシートの「拡張機能 → Apps Script」を開き、[gas/Code.gs](gas/Code.gs) と [gas/Startgg.gs](gas/Startgg.gs) を同じプロジェクトに保存します。既存のシートや本番デプロイと分けます。
2. Apps Script の「プロジェクトの設定 → スクリプト プロパティ」で下の項目を設定します。キーの値はブラウザや GitHub に公開しません。
3. シートを開き直し、「千スマ → このシートを保存先に設定」、「start.gg の対戦を取り込む」、「start.gg 定期反映を開始」を順に実行し、Google の権限を承認します。定期処理は運営用の１アカウントで設定します。
4. GAS をウェブアプリとしてデプロイします。「次のユーザーとして実行」はシートへ書き込めるデプロイ担当者とし、アクセス範囲は選手が使える設定にします。シートの共有は運営に限定します。
5. フロントエンドのローカル設定または Cloudflare のプレビュー環境に `VITE_GAS_URL` としてテスト GAS の `/exec` URL を設定し、`npm ci` と `npm run build` を実行します。出力先は `dist/` です。
6. 対戦が取り込めたら `STARTGG_REPORTING_ENABLED` を `true` にし、選手画面から初回報告、同じ勝者への訂正、勝者変更の本部案内を確認します。

| スクリプト プロパティ | 設定値 |
|---|---|
| `STARTGG_EVENT_SLUG` | start.gg のイベント URL、`tournament/…/event/…`、またはイベント ID。 |
| `STARTGG_API_TOKEN` | 対象イベントに結果を登録できるアカウントの API トークン。 |
| `STARTGG_REPORTING_ENABLED` | 初期値は停止。選手の結果報告を受け付けるときに `true`。 |
| `STARTGG_BLOCKED_SET_IDS` | 任意。報告を止める対戦 ID をカンマ区切りで指定。 |
| `STARTGG_BEST_OF_BY_ROUND` | 任意。例 `{"Winners Round 1":3,"Finals/Grand Final":5}`。キーには start.gg のラウンド名、必要に応じて「フェーズ名/ラウンド名」を指定。指定がない場合は対戦の BO3・BO5 設定を使い、未設定なら BO5。 |

## 本番運用

- 本番の接続先と公開 URL を確認後、各台の QR に `?station=1` から `?station=25` を付けます。取り込み済みの選手名を選んで対戦を検索し、再戦などはサイドやラウンドで絞り込みます。台番号は報告に記録されます。
- 選手は対戦カードを確認してそのまま送信します。新規報告には本人確認による出場者 ID が付かないため、「報告履歴」の出場者ID欄は空欄になります。
- 選手には「受付済み・反映待ち」と「start.gg 反映済み」を区別して表示します。「報告履歴」に変更前、報告内容、反映後が入り、「反映試行」に各試行が残ります。「要対応」行の再試行は「千スマ」メニューから行えます。
- 確定済みの対戦で勝者が変わる場合は本部で対応します。本部が start.gg で変更する前に「本部の訂正前後を記録」から `対戦ID 前` を記録し、変更後に `対戦ID 後` を記録します。後続対戦の控えも「本部訂正履歴」で確認できます。
- `Games` のファイター名とステージ名は英語です。登録名の表示・運営限定シートへの保管に関する start.gg の利用条件は、本番利用前に確認してください。

## 現行の手動転記版

`VITE_REPORT_MODE=manual` と、start.gg のイベントを設定していない GAS を使うと、従来のシート受付・承認と手動転記の画面を利用できます。GitHub の `main` への push は既存の Cloudflare 自動公開につながります。GAS は Apps Script 側で別途デプロイします。

## ローカル検証

```sh
npm ci
npm run build
node --test gas/startgg.test.mjs
```
